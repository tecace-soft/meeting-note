## What this product is

Meeting Note turns a meeting into usable knowledge.
A user records or uploads audio, the backend transcribes it (AssemblyAI) and summarizes it (Gemini), and the result is saved as a note with a summary, action items, and speaker-attributed segments.
The web app authenticates with Microsoft (MSAL / Azure AD) and integrates with MS Teams and OneDrive.
All note data lives in Supabase (Postgres) behind row-level security.
An unauthenticated request is rejected, and an authenticated one sees only its own rows, never another user's data.

On top of the raw pipeline the backend layers several higher-value subsystems: personal memory that folds across meetings, context-based speaker identification, a private meeting-knowledge extraction flow, and an MCP server so assistants (Claude, ChatGPT) can query a user's notes and personal context.

## How the pieces fit

The web frontend (`src/`) is the primary UI.
It talks to the Node backend (`workflow-server/`) for the transcribe / summarize pipeline and to Supabase directly for reading note data under RLS.
The backend also hosts the MCP server on the same process (merged to save hosting cost) and owns the edge-adjacent AI work (memory fold, insight extraction, speaker ID, knowledge extraction).
Supabase (`supabase/`) holds the schema, migrations, RLS policies, and Deno edge functions used for token exchange, signed audio URLs, profile generation, and admin.
A Flutter app (`meeting-note-mobile/`) is the mobile client, kept roughly at web parity.

Project의 요약 편집과 이름 변경은 `src/lib/notes/repository.ts`의 소유자 쓰기 메서드를 사용한다.
인증된 사용자 범위와 반환된 행을 확인한 뒤에만 화면을 성공 상태로 갱신한다.
`workflow-server`의 고정 버전 PGlite 개발 의존성과 `npm run test:note-rls`는 실제 migration의 note RLS를 메모리 DB에서 검증하며 CI의 `npm test`에도 포함된다.

백엔드 테스트는 `src/test-setup.ts`가 상속된 서비스 자격정보를 비우고 dotenv와 알림을 끄며, undici MockAgent로 외부 연결과 redirect를 차단한다.
`index.ts`를 import해도 서버나 worker가 시작되지 않으며, `startServer()`가 등록한 리소스는 반환된 정리 함수로 해제한다.
라우트 parity와 계약 테스트는 실제 dispatcher를 loopback 서버에서 실행하고 외부 서비스 경계를 합성 응답으로 대체한다.

## Running and keeping these docs current

- Structure auto-syncs: a committed pre-commit hook runs `node scripts/ai-native-docs/generate.mjs` and stages `docs/ai-native/`, so the structure region rides along with every commit (the hook only refreshes the structure region; recent history comes from git). No API key, never blocks on an LLM.
- One-time setup (each clone, once): point git at the committed hooks directory.

  ```bash
  git config core.hooksPath .githooks
  ```

- To refresh the hand-written narrative and the decision log after a meaningful change, run the `/update-docs` Claude Code slash command (it also runs the deterministic generator).
- To regenerate the structural regions by hand at any time: `npm run docs:ai-native`.
