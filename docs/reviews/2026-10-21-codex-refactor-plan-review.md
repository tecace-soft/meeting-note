## 5. [높음] 서버 실행 방법과 회사 서버 바인딩 규칙 충돌

위치: 계획 §5.1, T1-0a; `package.json:7`, `workflow-server/src/index.ts:3939`.

`server.listen(0)`은 loopback 전용이 아니다.
프런트의 기본 dev 명령은 `0.0.0.0`에 바인딩한다.
이는 이번 검토에서 전달받은 공용 AGENTS 규칙과 직접 충돌한다.
host 생략 동작은 [Node 공식 문서](https://nodejs.org/api/net.html#serverlistenport-host-backlog-callback)에 설명되어 있다.

수정 제안:

- 테스트는 `server.listen(0, '127.0.0.1')`로 명시한다.
- 기존 `workflow-server/src/knowledge/http.test.ts:52`가 선례다.
- 프런트 명령에는 `--host 127.0.0.1`을 붙인다.
- 백엔드 로컬 실행에도 loopback 설정을 마련한 뒤 VS Code 포워딩으로 확인하도록 수정한다.

## 9. [중간] import 가능화와 dotenv 이동의 검증 범위 부족

위치: 계획 T1-0a, T1-0b, §10; `workflow-server/src/index.ts:63`, `:315`, `:3800`.

listen만 막아도 `.env` 로드, 전역 dispatcher 교체, process 오류 핸들러 등록은 남는다.
따라서 import 가능하다는 것만으로 테스트 격리가 보장되지는 않는다.
현재 `.env` 경로 계산을 하위 `config/`로 그대로 옮기면 기준 디렉터리가 달라진다.

수정 제안:

- 테스트에서 실제 설정, 외부 통신, 알림을 차단한다.
- process 핸들러와 타이머 등록은 시작 함수가 소유하도록 명시한다.
- `.env` 경로와 실행 진입점 판정은 저장소 루트와 서버 디렉터리 실행, tsx 실행과 컴파일 결과 실행을 각각 확인한다.
