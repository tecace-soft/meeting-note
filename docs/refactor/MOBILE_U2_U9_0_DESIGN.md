## S11 제출 기록

첫 업로드와 POST 전에 JsonCacheStore에 사용자, 원본 키, noteId, fileId와 기록 시각을 저장한다.
같은 사용자와 같은 원본의 재시도와 앱 재시작은 두 id를 재사용한다.
로컬 녹음 업로드 뒤 최근 녹음으로 다시 선택해도 같은 fileId의 제출 기록을 재사용한다.
24시간 초과와 미래 시각 기록은 재사용하지 않는다.
저장 실패 시 제출하지 않는다.
기록 조작은 직렬화해 같은 원본의 동시 제출과 다른 원본의 저장이 서로 덮어쓰지 않게 한다.
job 완료와 첨부 처리 뒤 해당 사용자와 noteId의 기록만 지운다.
서버 실패나 응답 유실에는 기록을 남겨 다시 제출해도 같은 job으로 수렴하게 한다.
서명 URL, 토큰과 인증 정보는 제출 기록에 저장하지 않는다.
S11의 나머지 재시도 정책과 서버 변경은 이 PR에 없다.

## 화자 지정과 공유

수동 이름 입력, 저장된 화자 선택, Microsoft 연락처 선택과 제안 적용은 전사만 저장한다.
저장 직후 노트 상단에 이름과 별도 공유 동작을 표시한다.
Microsoft object id를 확인한 대상은 이 사람과 노트 공유 버튼으로 한 사람만 추가한다.
계정 id가 없는 대상은 공유 대상 선택으로 기존 공유 창을 연다.
이름이나 이메일만으로 계정 id를 추정하지 않는다.
제안의 화자 id는 저장된 화자 행의 id와 이름이 모두 맞아야 하며 직접 선택한 연락처는 그 연락처의 object id를 쓴다.
노트 소유자를 읽기와 쓰기에서 확인하고 UPDATE의 반환 id도 확인하며 0행은 오류다.
한 사람 추가는 읽은 shared_users의 정확한 값도 조건으로 검사한다.
NULL과 빈 배열을 구분하며 다른 기기의 철회나 추가와 경합하면 최신 목록으로 최대 3회만 재시도한다.
자기 자신과 이미 공유된 대상에게 다시 쓰지 않는다.
마지막 익명 화자 지정 뒤에도 동작을 유지하고 초기화, 재지정과 노트 이동 뒤의 오래된 동작은 쓰지 않는다.
이미 공유된 노트는 일괄 철회하거나 보정하지 않는다.
