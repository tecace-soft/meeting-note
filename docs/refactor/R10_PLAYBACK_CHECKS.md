# R10 재생 링크 갱신

## 변경 계약

기록 화면은 메타데이터 로드 실패 또는 15초 제한 시 해당 노트의 캐시만 지운다.
기존 note-audio-url 경로에서 새 링크를 한 번 받아 같은 구간을 다시 로드한다.
두 번째 실패 뒤에는 재생과 로딩 표시를 초기화하며 세 번째 자동 시도는 하지 않는다.
새 링크의 발급이 거부되면 추가 로드 없이 기존 오류 처리로 끝낸다.
실패한 두 번째 링크도 캐시에서 지워 다음 수동 시도에 재사용하지 않는다.
다른 노트의 링크는 유지하며 늦게 끝난 preload가 폐기한 링크를 다시 캐시하지 않게 한다.
자동 재생 거부와 오디오 범위 밖 구간은 링크 재발급 사유가 아니다.
화면 이동과 언마운트는 진행 중 메타데이터 대기와 타이머를 취소한다.

새 노트 화면은 저장소 경로가 있으면 원래도 매 재생마다 링크를 새로 받는다.
이 화면에도 메타데이터 로드 실패 시 현재 noteId의 접근 권한을 확인하는 경로로 한 번 재발급하고 각 로드에 15초 제한을 적용한다.
첫 오류에서 React의 미디어 오류 핸들러가 지운 재생 상태와 구간 종료 위치는 재시도 성공 뒤 복원한다.
서명 요청 함수만 먼저 별도 커밋으로 옮겼으며 기존 요청 헤더와 오류 문구는 유지했다.
서버, edge function과 DB는 변경하거나 배포하지 않는다.

## 오프라인 검증

실제 서비스나 실제 .env를 쓰지 않고 URL 발급과 미디어 이벤트를 가짜로 제어한다.
기록 화면의 실패 재현 테스트 5개와 새 노트 화면의 실패 재현 테스트 3개는 수정 전에 실패했다.
재시도 성공, 두 번째 실패, 같은 URL 반환, 권한 거부, 다른 노트 캐시 유지, 메타데이터 제한과 언마운트를 검사한다.
기록 화면 훅과 실제 두 화면의 마운트 테스트에서 재생 상태와 구간 종료 위치 복원을 검증한다.
기존 로드 실패 즉시 초기화 계약은 재발급 한 번 뒤 성공 또는 두 번째 실패 뒤 초기화 계약으로 바꿨다.
15초 경계 테스트는 자동으로 흐르지 않는 fake clock을 쓰고 단언 전에 real timer로 되돌린다.

## Andrew 통합 E2E 확인

다른 진행 작업이 끝난 뒤 한 번에 확인한다.
기록 화면을 오래 열어 링크가 만료된 뒤 구간 재생이 새 링크 한 번으로 복구되는지 확인한다.
새 노트 화면도 첫 로드 실패 뒤 한 번만 재발급하고 같은 구간을 재생하는지 확인한다.
접근 권한 철회 또는 두 번의 로드 실패 뒤 로딩 표시가 남지 않는지 확인한다.
새 구간이나 다른 노트를 선택한 뒤 이전 비동기 응답이 예전 녹음을 재생하지 않는지 확인한다.
재시도 성공 뒤에도 선택한 구간 끝에서 재생이 멈추는지 확인한다.
