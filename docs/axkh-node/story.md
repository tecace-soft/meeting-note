Meeting Note는 Microsoft 인증 웹 앱에서 오디오 전사와 Teams 채팅 접근으로 시작했다.
이후 AssemblyAI와 Gemini 위에서 전사와 요약을 처리하는 전용 Node 파이프라인(workflow-server)이 생겼다.

그 뒤로 작업은 크게 다섯 갈래로 이어졌다.

- 안정성과 규모: 재시작 시 고아 작업 정리, 더 큰 업로드와 더 긴 녹음, 요약 임계 경로의 지연 개선, 오류 처리 정비.
- 메모리: 회의를 가로질러 액션 아이템, 협업자, 프로젝트, 주제를 접어 쌓는 개인 메모리 계층. 평가 하네스로 측정한 뒤 출시했고, 요약 생성과 MCP 툴에 연결했다.
- 화자 식별: 음성 지문이 아닌 컨텍스트 기반 방식. 단순 커버리지보다 같은 팀 안에서의 구분력을 백테스트로 측정하며 조정했다.
- MCP와 커넥터: 호스팅 비용을 줄이려고 MCP 서버를 백엔드 프로세스에 합쳤고, Claude와 ChatGPT가 연결되도록 OAuth와 인증을 규격에 맞게 다듬었다.
- 비공개 회의 지식: 정책으로 통제되는 추출과 안정적인 비공개 전달을 만들고, 프로젝트 단위 RLS를 강화했다.

2026-10에는 세 가지가 더해졌다.

- AX-KH 피드백/이슈 기능 이식: 서버가 권한을 강제하는 형태로 AX-KH 명세를 옮겼다.
- 인증 강화: 로그인과 백엔드 호출에서 이메일 도메인이 아니라 Microsoft 테넌트만 신뢰한다.
- 결정 기록 구조화: 결정을 파일 하나씩 기록하고, 변경 파일이 활성 결정과 겹치면 경고한다.
